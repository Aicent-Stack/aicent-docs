# No stop button on the wire | Aicent Stack

29 Oct 2026 · [Read the full article](https://blog.aicent.com/no-stop-button-on-the-wire/) · [Chinese version](https://blog.aicent.com/zh/no-stop-button-on-the-wire/)

Whenever authority must be revocable, the same shape of question resurfaces: who stops the agent that is already running? And the same shape of answer keeps being proposed — a bigger vocabulary, a richer state machine, a halt signal carried on the wire. This piece answers from the two-pillar design itself, on its own terms: the wire carries no stop button, and that is by design. The deadline travels in the first verification answer, so a runtime holds its own halt time from the moment it starts. The lease window bounds how long anything can persist past a revocation — one window, then the next verification names the reason. A delegation chain is safe because each hop verifies fresh, not because a master switch exists; standing does not transfer between hops, so the chain can only run as far as fresh answers let it. And the closed set of standing values audits while richer runtime state machines implement — the two must never be fused, because a vocabulary that tries to standardize every operational state stops being one an audit can re-derive. The protocol delivers the deadline, the window, and the reason; the calling layer swings the halt. The schemes deliver the knife and do not swing it.
